## 第 1 步 · 建目录

```bash
mkdir -p ~/code /data2/yjr/projects
```

**为什么分两块盘**：

| 位置 | 是什么 | 放什么 |
|---|---|---|
| `/home/yjr` | 系统盘上的个人目录 | 代码、Python 环境 |
| `/data2/yjr` | 单独划给我的数据盘 | 数据集、模型权重 |

往 `/home` 塞数据集会**影响全组登录**（`/home` 是共用的）。

**实测**：`/home` 共 7.0 T（余 2.8 T）、`/data` 共 9.1 T（余 2.1 T）、`/data2` 共 5.5 T（几乎全空）。

## 第 2 步 · 传代码

```bash
rsync -avz 本地目录/ yjr@<server>:~/code/
```

`rsync` 是**增量传输**——第二次只传改动的文件，不会把整个项目重传。

**实测**：训练脚本传到远端后可正常执行。

## 第 3 步 · 建环境（这一步踩坑最多）

### 实测发现的三个约束

| 检查 | 结果 |
|---|---|
| `conda` 命令 | ❌ 不在 PATH 里 |
| `/opt/anaconda3` | ✅ 装着 conda 24.9.2 / Python 3.12.7 / pip 24.2 |
| 系统 `python3` | ✅ 3.10.12，但 **`python3 -m pip` 和 `ensurepip` 都不存在** |
| `python3 -m venv` | ⚠️ 能建，但建出来的 venv **没有 pip** |
| `/opt/anaconda3/envs` | ❌ 不可写 |

### 最终方案

```bash
/opt/anaconda3/bin/python -m venv ~/venv/sgg
source ~/venv/sgg/bin/activate
pip install torch --index-url https://download.pytorch.org/whl/cu121
```

**为什么这样能行**：anaconda 自带的 Python **有 ensurepip**，所以建出来的 venv 自带 pip。而系统 python3 缺这个模块。

**好处**：环境在自己的目录里，**不需要 sudo，不影响其他成员**。

**实测速度**：`download.pytorch.org` 约 **12 MB/s**（比清华源快 15 倍），780MB 的 torch 几分钟下完。

## 第 4 步 · tmux 挂任务

```bash
tmux new -d -s w2 "python your_train.py > train.log 2>&1"
```

**解决什么问题**：直接在本地终端跑训练，一旦合上笔记本或网络抖动，SSH 断开，**服务器上的进程会被一起杀掉**，几小时的计算全废。

tmux 把任务挂在服务器端的虚拟终端里，**与本地连接彻底解耦**。

常用三条：
```bash
tmux new -s 名字        # 建会话
# 按 Ctrl+B 松开，再按 D   # 脱离（任务留在服务器）
tmux attach -t 名字     # 回来看
tmux ls                 # 看有哪些会话
```

---

## 第 5 步 · 断开重连验证（这一步才算验收）

**为什么不能只截一张 `tmux ls`**：证明不了中间断过。老师要的是「断过之后还在」。

**方法**：三条**独立** SSH 连接

| 连接 | 动作 | 观察到 |
|---|---|---|
| 第 1 条 | 建会话、启动任务 | 日志输出 `tick 0`、`tick 1` |
| —— | **断开** | |
| 第 2 条 | 全新连接 | 会话仍在，日志到 `tick 8`，进程号未变 |
| —— | **再断开** | |
| 第 3 条 | 全新连接 | 日志到 `tick 14`，总行数 15 |

日志行数 **2 → 9 → 15** 持续增长 = **断开没有中断任务**。

## 附加 · GPU tensor 运算

```python
import torch
print(torch.cuda.is_available())      # True
print(torch.cuda.device_count())      # 3
x = torch.randn(4096, 4096, device="cuda")
y = torch.randn(4096, 4096, device="cuda")
z = x @ y                             # 真算
```

**为什么单独验这一步**：`nvidia-smi` 能看到卡，**不代表你的代码能用上**。驱动不匹配、CUDA 版本不对、torch 装成 CPU 版——这几种情况 `nvidia-smi` 照样正常，但 `is_available()` 返回 `False`。

### 实测结果

| 项 | 值 |
|---|---|
| `cuda.is_available()` | **True** |
| `device_count` | **3** |
| 设备 | 3 × NVIDIA Tesla L20，各 46068 MiB，计算能力 8.9 |
| 驱动 | 595.91.07（支持到 CUDA 13.2） |
| CUDA 工具包 | `/usr/local` 下有 11.7 / 12.2 / 12.4 / 12.6 / 12.8 |
| 10 次 4096×4096 矩阵乘 | **0.055 秒** |
| 显存占用 | 200 MB |

### 与本机的对照

| | 本机 | L20 |
|---|---|---|
| 显卡 | AMD Radeon 780M 核显 | 3 × Tesla L20 |
| `cuda.is_available()` | **False**（硬件定局） | **True** |

一 False 一 True，正好证明**不是没装好，是硬件不同**。

> 注：组内文档记载为 2 张 L20，实机实测为 **3 张**（合计 138 GB 显存）。
