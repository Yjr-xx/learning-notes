# W1 笔记 · Linux 长任务与进程管理命令速查

日期：2026-10-28　对应：老师清单 1.1 第 3–6 条

> **状态说明（2026-11-03 更新）**：本机是 Windows + AMD 核显，**没有 Linux 环境、没有 NVIDIA 显卡**。组内 L20 服务器账号**已于 2026-11-03 开通**，但这份表仍是**按文档整理的命令速查**——`tmux` / `rsync` / `nvidia-smi` 三项**尚未在真实机器上实跑**，下表保持 ⬜，跑过之后才改 ✅。已在 Git Bash 里实际用过的会标 ✅。

## 一、远程连接与传文件（老师 1.1 第 3 条）

| 命令 | 干什么 | 状态 |
|---|---|---|
| `ssh 用户名@服务器IP` | 登录到另一台机器，之后敲的命令都在那台上执行 | ⬜ 待实测 |
| `scp 本地文件 用户名@IP:/目标路径` | 把单个文件传过去（小文件够用） | ⬜ 待实测 |
| `rsync -avz 本地目录/ 用户名@IP:/目标目录/` | 传整个目录，且**只传改动过的部分**（比 scp 快，支持断点续） | ⬜ 待实测 |

`-avz` 三个字母：`a` 保留权限与时间戳、`v` 显示过程、`z` 传输时压缩。

## 二、看进程与资源（老师 1.1 第 4 条）

| 命令 | 干什么 | 状态 |
|---|---|---|
| `ps aux \| grep python` | 找出当前跑着的 python 进程，拿到 PID | ⬜ |
| `top` / `htop` | 实时看 CPU、内存、哪个进程在吃 | ⬜ |
| `kill -9 PID` | 强杀一个卡死的进程（先 `ps` 找到 PID） | ⬜ |
| `nvidia-smi` | 看显卡：显存占用多少、谁在用、温度 | ⬜ **本机无 N 卡，永远不会输出**，只能在服务器上看 |
| `df -h` | 看磁盘还剩多少（`-h` = 人类看得懂的 GB/TB） | ✅ 在 Git Bash 里用过 |

`nvidia-smi` 输出里最该看三列：**GPU-Util（利用率 %）、Memory-Used（已用显存）、PID（谁占的）**。组里的规矩是「用完必须释放，占着别人的卡最忌讳」。

## 三、长任务：断开也不能停（老师 1.1 第 5 条）

**问题**：直接跑训练，一关终端或网络一断，进程就被杀，几小时的训练白跑。

**解法**：`tmux` 开一个"会话"，进程挂在会话里，与终端解绑。

| 操作 | 命令 | 说明 |
|---|---|---|
| 新建会话 | `tmux new -s train` | `train` 是会话名，随便起 |
| 在里面跑任务 | `python train.py 2>&1 \| tee train.log` | 屏幕看得见，同时写进日志文件 |
| **离开但不停** | 按 `Ctrl+b`，松开，再按 `d` | detach（脱离），进程继续跑 |
| 看有哪些会话 | `tmux ls` | 会显示 `train: 1 windows (created ...)` |
| 回来 | `tmux attach -t train` | 重新接上，看到之前的输出还在滚 |
| 结束会话 | `exit` 或在里面按 `Ctrl+d` | 会话消失 |

**判据**：`tmux ls` 里会话还 active、`attach` 回去任务还在跑 = 真的做到了「断开不中断」。

## 四、看日志（老师 1.1 第 6 条）

| 命令 | 干什么 | 状态 |
|---|---|---|
| `tail -f train.log` | **持续滚动显示**日志最后几行，训练在打新内容就实时冒出来 | ⬜ 待实操 |
| `tail -n 100 train.log` | 只看最后 100 行，不跟随 | ⬜ |
| `grep -n "loss" train.log` | 在日志里搜关键词并带行号 | ✅ 在 Git Bash 里用过类似命令 |
| `cat train.log \| grep -i error` | 找报错 | ✅ |
